Stage 1 — the four fixes

What is wrong now, and what we replace it with.

Problem now
Fix
1. Never follows references
It runs 4 keyword searches and stops. If a paper uses different words, it is invisible — and that is the paper that makes your gap fake.
Take the papers that passed screening. Pull what they cite and who cites them. Screen those too. Repeat.
Both OpenAlex and Semantic Scholar give this free. This is what grows the wide pile to a few hundred.
2. Matches by counting shared words
“server room chilled water” scores near zero against “data centre cooling”. This is half the ranking score today.
Match on meaning, not words, using a small model that runs on your own machine. Free, fast, no API cost, same answer every time.
For the 20 core papers only, a cheap LLM also reads the abstract and says yes or no with a reason.
3. No retraction check
A withdrawn paper can quietly become the evidence behind a research gap.
OpenAlex already tells you if a paper is retracted, and Crossref lists withdrawal notices. Check both, drop it, and write down why.
Also drop editorials and covers, which OpenAlex flags separately.
4. Punishes published preprints
An arXiv paper scores 0.18 for credibility even if it appeared in a good journal two years later.
Before scoring, go looking for the published version by title and author. If it exists, use it instead and note the swap.
Your merge step already joins them when both happen to turn up. This makes it deliberate.
Does this stage need self-improvement?  —  Yes, and it is the easiest place to do it honestly

You already produce the answer key by accident. Every time you approve the paper list and remove a paper, you have told the system it was wrong. Every paper you keep is a correct call. Nobody has to label anything.

So over runs the system can learn four small things: which kinds of search query actually return papers you keep, which venues in this field are worth trusting, where to set the include/exclude line, and how to weight the ranking instead of the hand-picked 0.50 / 0.20 / 0.12 / 0.10 / 0.08.

Keep it small. A few runs gives a few hundred decisions. That is enough to tune a handful of numbers. It is not enough to rewrite prompts freely. And hold back some runs to check the tuning actually helps, or you will just fit it to your first three topics.
